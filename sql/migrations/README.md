# 数据库迁移约定

生产 MySQL 的表结构与本地代码一起演进。每次涉及表、字段、索引、约束或种子数据的 SQL 变化，必须创建一条不可修改的增量迁移，并在 VPS 的 `quant_data` 中执行。

## 执行原则

1. 不重建、不清空既有库；迁移只能新增或进行可验证的兼容性变更。
2. 每次执行先写入/核对 `schema_migration`，防止重复运行。
3. 迁移前后记录关键旧表行数及新结构，发生错误必须回滚当前迁移并报告。
4. 不在迁移文件中保存密码、Token 或服务器连接信息。

## 当前基线

- 版本：`20260813_001_trade_run_foundation`
- 源文件：`../trade_run_schema.sql`
- 内容：交易实例、计划、成交、资金、持仓、审计等新领域表及三条策略版本种子。

后续迁移按 `YYYYMMDD_NNN_说明.sql` 创建在本目录中；已在线上执行的迁移不得改写，只能追加新版本。

迁移由 `scripts/run_mysql_migration.py` 执行。它会在目标库建立并检查 `schema_migration`，按迁移文件 SHA-256 校验版本；同名文件变更会被拒绝，避免代码与数据库结构悄悄漂移。
